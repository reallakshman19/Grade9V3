MIC-PHY-KIN-2D-INDEPENDENT-COMPONENTS

1 · Independent equations, one physical clock

R1 · Shared state

Predict

If you calculate x at 2 s and y at 5 s, can you combine those values into the position of one particle?

Canonical crux

Perpendicular components may be solved separately because each axis equation contains only that axis's quantities, but both equations describe the same object at the same physical time.

Representation → mathematics

r(t) = ( x(t), y(t) )
x(t₁), y(t₂) with t₁ ≠ t₂ are individually valid samples but not one simultaneous state.

Misconception repair

Wrong: “Independent axes can use independent times.” Repair: independence belongs to the equations; the physical event still has one clock.

Try first

A particle has x(2)=6 m, y(2)=4 m and y(5)=10 m. Which ordered pair is a valid state at 2 s?

Check
(6 m, 4 m) is the valid 2 s state. Pairing x(2) with y(5) creates a mixed-time ghost state.
MIC-PHY-KIN-2D-CONSTANT-ACCELERATION

2 · Apply constant-acceleration kinematics component by component

R2 · Same interval

Condition first

The one-dimensional constant-acceleration equations can be applied to each perpendicular component independently when aₓ and aᵧ are each constant over the same time interval.

Two copies of the same model

x-component: vₓ = uₓ + aₓt; Δx = uₓt + ½aₓt².
y-component: vᵧ = uᵧ + aᵧt; Δy = uᵧt + ½aᵧt².
Shared state: use the same event time t when the two component answers describe one physical event.

Boundary

If either component acceleration changes during the interval, the standard constant-a equations are not exact for that whole component history.

Worked anchor

uₓ=6 m/s, aₓ=0; uᵧ=8 m/s, aᵧ=−2 m/s². At t=3 s: Δx=18 m, Δy=15 m. Those values belong to one 3 s state because both use the same clock.

Transfer

At t=4 s, x has been computed correctly. Your y result was computed at t=3 s. What must you do before reporting the particle's 2D position?

Check
Recompute or sample y at 4 s. Component equations may be separate, but the final ordered pair for one state must share the event time.
MIC-PHY-KIN-PROJECTILE-MODEL

3 · Select the gravity-only projectile model, then select the event

R3 · Model + event

Model choice

After release in the ideal near-Earth projectile model, no new kinematic laws appear: use the same component equations with aₓ = 0 and aᵧ = −g when +y is upward.

Event leaves — same model, not new capabilities

Apex

Use vᵧ = 0 as the event condition. Horizontal velocity does not vanish merely because the vertical component does.

Same-height return

Use the actual vertical displacement condition Δy = 0 between equal-height endpoints; do not confuse it with the apex condition.

Horizontal launch

Set uᵧ = 0 because of the launch direction. Find the event time from vertical geometry, then share that time with x.

Unequal-height landing

Use the actual Δy = yf − yi and retain the actual uᵧ. Unequal landing height is geometry, not a reason to invent a new model.

Misconception repairs

Apex: vᵧ=0 does not mean total velocity is zero when vₓ remains nonzero.
Same-height: Δy=0 is an endpoint relation, not a statement that vertical motion never occurred.
Horizontal launch: uᵧ=0 is an initial condition; vertical velocity changes immediately under gravity.
Model validity: drag, changing g, moving launchers and relative-motion frames require a different or extended model and are outside this packet.

Worked anchor

Horizontal launch from 20 m with g=10 m/s²: vertical equation −20 = 0·t − ½(10)t² gives t=2 s. If uₓ=6 m/s, horizontal displacement at that same event is 12 m.

Fresh transfer

A projectile has uᵧ=10 m/s and lands 15 m below its launch point. Which vertical facts belong in the position equation, and which tempting “horizontal-launch” shortcut must you reject?

Check
Keep the actual uᵧ=10 m/s and use Δy=−15 m (for +y upward). Reject uᵧ=0 because that condition applies only to a horizontal launch.
